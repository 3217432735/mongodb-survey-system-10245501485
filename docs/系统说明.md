# 系统说明

## 1. 项目目标

本系统实现课程大作业第一阶段的要求：注册用户可以创建问卷、设置题目和跳转规则、发布链接，其他登录用户通过链接填写，创建者可以查看统计结果。系统只做课程作业需要的基本功能，界面尽量简单，重点放在 MongoDB 数据结构、后端校验和跳转逻辑上。

## 2. 用户角色

系统只有两种使用状态，没有单独的管理员。

- 未登录用户：可以注册和登录。打开问卷链接时会被要求先登录。
- 已登录用户：既可以创建和管理自己的问卷，也可以填写别人发来的问卷。

用户只能看到自己创建的问卷。填写别人问卷时，只能拿到公开的问卷内容，不能拿到创建者信息和其它答卷。

## 3. 系统结构

系统采用前后端分离不彻底的结构：页面是静态 HTML、CSS 和原生 JavaScript，后端提供 JSON 接口。

```text
浏览器页面
  ├─ 登录/注册
  ├─ 我的问卷
  ├─ 问卷编辑
  ├─ 填写问卷
  └─ 统计结果
        │  fetch + session cookie
        ▼
Express 应用
  ├─ /api/auth       账号接口
  ├─ /api/surveys    问卷和题目管理
  ├─ /api/fill       填写和提交
  ├─ validation.js   题目和答案校验
  └─ jump.js         跳转规则计算
        │
        ▼
MongoDB
  ├─ users
  ├─ surveys
  ├─ questions
  ├─ responses
  └─ sessions
```

## 4. 页面与流程

### 4.1 注册和登录

注册时填写用户名、密码和确认密码。用户名限制为 3 到 20 位字母、数字或下划线，密码至少 6 位。注册成功后直接进入问卷列表。

登录状态用 session 保存，session 放在 MongoDB 的 `sessions` 集合里，所以服务重启后登录状态不会马上丢失。浏览器只保存一个 `connect.sid` cookie。

### 4.2 创建问卷

在“我的问卷”页面填写标题、说明、截止时间，选择是否允许匿名、是否允许重复填写。创建后进入编辑页，此时问卷状态是草稿。

草稿状态下可以：

- 修改问卷基本信息
- 添加题目
- 编辑题目和跳转规则
- 删除最后一题
- 发布问卷
- 删除整份草稿

发布后题目和基本设置锁定，避免新答案和旧题目对不上。发布后可以关闭问卷，关闭后不能再填写，但统计仍然能看。

### 4.3 添加题目

题目类型有四种：

- 单选题：至少两个选项，可设置必答。
- 多选题：至少两个选项，可以设置最少选择、最多选择或必须选择几个。
- 文本填空题：可以设置最少字数和最多字数。
- 数字填空题：可以设置最小值和最大值，可以要求只能填整数。

每道题保存后都有一个从 1 开始的题号。因为只允许删除最后一题，题号始终连续，跳转规则里的“跳到第几题”不会因为中间删题而错位。

### 4.4 发布和填写

发布后系统生成一个 8 位公开编号，链接形式是：

```text
http://localhost:3000/survey/campus26
```

这个地址会跳到填写页面。填写页一次只显示一道题，用户点“下一题”后，系统根据当前答案决定下一题题号。如果规则跳到后面的题，中间的题会被跳过；如果没命中规则，就按题号顺序进入下一题。

用户可以点“上一题”返回修改。修改后重新往下走时，原来后面的答案会被清掉，避免把旧分支的答案提交上去。

填写页支持：

- 必答题不填时不能继续
- 多选题数量不符合时提示
- 文本长度不符合时提示
- 数字不是整数或超出范围时提示
- 匿名提交
- 同一用户重复填写（问卷允许时）

### 4.5 统计

创建者在统计页可以看到：

- 总答卷数
- 每道题的回答人数
- 单选题每个选项的人数和百分比
- 多选题每个选项被选次数和选择率
- 数字题的平均值、最小值、最大值
- 文本题的所有填写内容

统计按“回答本题的人数”做分母。因为跳题会让一部分人没看到某道题，所以不能直接用总答卷数当分母。

## 5. 问卷状态

| 状态 | 说明 | 可做的操作 |
| --- | --- | --- |
| draft | 草稿 | 改设置、加题、改题、发布、删除 |
| published | 已发布 | 填写、查看统计、关闭 |
| closed | 已关闭 | 查看统计，不能再填写 |

如果问卷设置了截止时间，到了时间即使状态还是 published，填写接口也会拒绝并提示已截止。

## 6. 并发和权限

- MongoDB 本身可以处理多个用户同时提交，答卷是独立文档，不共享数组。
- 每个管理接口都会检查 `owner_id`，不是创建者返回 404，避免暴露问卷是否存在。
- 填写接口只返回公开字段，不返回 `owner_id` 和内部设置。
- 匿名答卷不保存用户编号和用户名。
- 限制重复填写时，用 `respondent_key` 判断是否填过，不把匿名用户身份写进答卷。

## 7. 没有做的内容

这一阶段没有做复杂界面、题目拖拽排序、问卷复制、图表库、导出 Excel、邮件通知等功能。这些不是初始需求，先保证核心流程跑通。

## 8. 第二阶段题目库与版本管理

第二阶段新增“题目库”页面。用户可以创建常用题目，也可以把问卷草稿中的题目加入题库。
题库中的题目可以共享给指定用户名；被共享用户登录后可以在自己的题库列表和问卷编辑页中选择。

每道题库题目由一个固定的题目根记录和多个不可变版本组成：

- 题目根记录保存创建者、共享用户、是否在题库以及当前版本。
- 每个版本保存题干、题型、选项、必答和校验条件。
- 新版本保留上一版本编号和派生来源，不覆盖旧版本。
- 恢复旧版本时生成一个新的当前版本，历史记录仍然保留。

问卷添加题库题目时，会把所选版本复制成当前问卷的题目快照。问卷只读取自己的
`questions` 文档，因此题库更新不会改变已发布问卷、其他问卷或历史答卷。

问卷编辑页支持选择题目根和具体版本。编辑已有题目时，可以勾选“同时创建题库新版本”：

- 勾选后，题库生成新版本，当前问卷引用新版本。
- 未勾选且题目内容发生变化时，当前问卷转为独立题目副本，不修改原题库。
- 只修改问卷专属的跳转规则时，题库关联保持不变。

题目库页面可以查看版本链、问卷使用情况和跨问卷统计。跨问卷统计只汇总当前账号自己创建的问卷，
避免共享用户在统计页面看到其他账号的答卷明细。
