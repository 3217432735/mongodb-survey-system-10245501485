# 第二阶段需求实现说明

## 1. 改造原则

第二阶段在现有 Node.js、Express 和 MongoDB 项目上增量开发，保留第一阶段的账号、问卷、
题型、跳转、校验、填写和单问卷统计功能。没有重新创建一套问卷系统，也没有删除第一阶段的主要集合。

旧数据中的 `questions` 文档继续作为问卷题目快照使用。第二阶段新增题目根和题目版本两个集合，
通过启动时的幂等迁移把旧题目关联到题目根，不修改旧答卷。

## 2. 需求与实现对应

| 需求变更 | 实现内容 |
| --- | --- |
| 保存常用题目，重复使用 | 新增题目库页面和 `/api/library/questions` 接口；题目加入题库后可以被多份问卷选择 |
| 共享题目给其他用户 | 题目根保存共享用户列表；被共享用户可以在题库和问卷编辑页使用 |
| 修改不得影响已发布问卷 | 问卷保存所选版本的独立快照；已发布问卷仍禁止修改；新版本不覆盖旧快照 |
| 记录修改历史 | `question_versions` 保存版本号、上一版本和派生来源；页面显示版本链 |
| 恢复旧版本 | 恢复操作复制目标版本生成新的当前版本，历史版本不删除 |
| 不同版本同时存在 | 题目根下允许多个版本；从题库添加时可选择具体版本 |
| 查看题目被哪些问卷使用 | 按题目根查询问卷题目快照，返回问卷、题号、引用版本和问卷状态 |
| 题库管理与从题库选题 | 题目库支持创建、加入题库、新建版本、共享、历史、使用情况和统计；问卷编辑页可从题库选题 |
| 单个题目跨问卷统计 | 按题目根关联多份问卷的题目快照，汇总当前用户的答卷 |

## 3. 数据结构变化

第一阶段主要集合保持不变：

- `users`
- `surveys`
- `questions`
- `responses`
- `sessions`

新增集合：

- `question_roots`：保存题目身份、创建者、共享用户、题库状态和当前版本。
- `question_versions`：保存不可变题目内容，包括版本号和来源关系。

`questions` 增加三个兼容字段：

- `library_root_id`
- `library_version_id`
- `derived_from_library_version_id`

## 4. 关键流程

### 4.1 创建题库题目

1. 用户填写题干、题型、选项和校验条件。
2. 系统将该题规范化，忽略问卷专属跳转规则。
3. 创建题目根和 v1 版本。
4. 题目根标记为已加入题库。

### 4.2 从题库添加到问卷

1. 用户选择题目和具体版本。
2. 后端检查题目是否由本人创建或已共享给本人。
3. 系统把版本内容复制到当前问卷的 `questions` 文档。
4. 问卷记录题目根和版本编号，后续修改题库不会修改该快照。

### 4.3 编辑问卷中的题库题目

1. 用户只修改跳转规则时，题目继续关联原题库版本。
2. 用户修改题干、选项或校验条件并勾选创建新版本时，题库新增版本，问卷引用新版本。
3. 用户不创建新版本时，题目转为问卷独立副本，不修改题库。
4. 已发布问卷仍不能修改题目。

### 4.4 恢复旧版本

系统读取目标历史版本，并复制其内容生成新的当前版本。新版本记录恢复来源，
但不覆盖原有的后续版本。

## 5. 兼容性处理

- 应用启动时自动执行旧题目迁移。
- 迁移逻辑可以重复运行；已有关联的题目不会再次迁移。
- 旧问卷的 `questions` 文档内容和答卷不变。
- 第一阶段接口字段保持原样，只增加题目版本相关字段。
- 原有题目测试与新增题目库测试一起运行，保证旧功能没有退化。

## 6. 新接口与页面

| 类型 | 内容 |
| --- | --- |
| 页面 | `/questions.html` 题目库管理与版本历史 |
| 页面 | `/builder.html` 增加从题库选题和创建版本选项 |
| API | `/api/library/questions` 题目库增查改和版本管理 |
| API | `/api/library/questions/:id/usage` 使用情况 |
| API | `/api/library/questions/:id/stats` 跨问卷统计 |
| API | `/api/surveys/:id/questions/from-library` 向问卷添加题目版本 |

## 7. 测试结果

第一阶段 13 项测试继续通过，第二阶段新增一组覆盖创建题库、版本隔离、共享、使用情况、
版本恢复和跨问卷统计的测试。总计 14 组测试全部通过。
