# 关键逻辑说明

## 1. 跳转规则的保存方式

跳转规则存在每道题的 `jump_rules` 数组里，按数组顺序匹配。结构分三种：

单选题：

```javascript
{ condition: { option: "A", match: "any" }, target_order: 4 }
```

多选题：

```javascript
{ condition: { option: "D", match: "any" }, target_order: 6 }
```

数字题：

```javascript
{ condition: { op: "gte", value: 30 }, target_order: 6 }
```

数字题支持的比较操作有：`eq` 等于、`ne` 不等于、`gt` 大于、`gte` 大于等于、`lt` 小于、`lte` 小于等于、`between` 区间。

## 2. 前端怎么跳

填写页把题目按 order 放进 Map。用户答完当前题后：

```text
读取当前答案
  ├─ 校验不通过 → 显示错误，不往下走
  └─ 校验通过
        ├─ 按顺序检查 jump_rules
        │    ├─ 命中第一条 → 下一题 = target_order
        │    └─ 都不命中 → 下一题 = 当前题号 + 1
        └─ 没有下一题 → 提交
```

前端只保存实际经过的题号，不把跳过题目的答案带下去。用户点“上一题”改了答案后，后面的旧路径会被截断，防止跳到另一条分支时还带着旧答案。

## 3. 后端为什么还要再算一遍

前端计算只是为了操作方便，不能当作可信结果。提交接口会：

1. 根据提交的 answers 按题号排序；
2. 从第 1 题开始，用同样的规则算出实际路径；
3. 只校验路径上的题目；
4. 如果必答题没填，返回错误；
5. 如果答案类型、范围、数量不对，返回错误；
6. 把路径上的答案重新整理后保存。

这样即使有人绕过页面直接发请求，也不能提交一条和跳转规则不一致的答卷。

## 4. 路径计算的伪代码

```text
order = 1
path = []
visited = 空集合

while order 存在 and order 没访问过:
    把 order 加入 path 和 visited
    question = 题号 order 的题目
    answer = 这份答卷里题号 order 的答案
    找到 question.jump_rules 中第一条匹配 answer 的规则
    if 找到:
        order = 规则.target_order
    else:
        order = order + 1
```

编辑跳转规则时限制只能跳到后面的题，所以正常数据不会出现死循环。`visited` 只是额外保护。

## 5. 校验顺序

服务端的校验顺序是：

1. 问卷是否存在、是否发布、是否关闭、是否过截止时间；
2. 是否登录；
3. 是否允许重复填写；
4. 计算路径；
5. 路径上的每题：是否为空、是否必答；
6. 按题型校验答案；
7. 整理答案并写入 responses。

把问卷状态和权限放在答案校验前面，可以让用户先看到“问卷已关闭”这类更直接的原因。

## 6. 匿名和限填一次

匿名答卷不保存 `respondent_id` 和 `respondent_name`。但如果问卷设置了每人只能填一次，又需要判断是不是同一个人。

做法是用 HMAC：

```text
respondent_key = HMAC-SHA256(用户编号 + ":" + 问卷编号)
```

这个值只存在服务端，用来查询该用户在这份问卷下有没有答卷。统计页面不显示这个字段，创建者也不能通过它反推出用户是谁。

## 7. 统计的分母

跳题会导致不同题目的回答人数不同。例如第 5 题只有一部分人会看到，所以：

- 单选题百分比 = 该选项人数 / 回答本题人数
- 多选题选择率 = 选该选项人数 / 回答本题人数
- 数字题平均分只对回答本题的数字求平均
- 文本题只列出有内容的答案

统计接口每次根据 responses 实时计算，不单独维护统计表，避免答卷和统计不一致。

## 8. 题目版本与问卷快照

一条题目根记录表示“这仍然是同一道题”，版本记录表示它在不同时期的具体内容。
问卷添加题目时只保存所选版本的副本，不直接引用可变的当前版本：

```text
question_roots
  ├─ v1 版本
  ├─ v2 版本
  └─ v3 版本

问卷 A -> 题目快照 v1
问卷 B -> 题目快照 v2
```

修改 v1 的副本不会改变 v2，新建 v3 也不会改变问卷 A 或问卷 B。问卷发布后仍然禁止修改题目，
因此答卷中的 `question_id` 始终能找到当时的题目内容。

## 9. 题目共享

题目创建者可以把题目根共享给另一个用户名。共享后，被共享用户可以：

- 在题库列表中看到该题。
- 选择当前版本或任意历史版本加入自己的问卷。
- 查看版本历史。

共享用户不能修改原题目根或创建原题目的新版本。若共享用户编辑题目并选择保存新版本，
系统会以当前用户为创建者建立一个新的题目根，保留派生来源。

## 10. 恢复历史版本

恢复操作不删除后续版本，也不直接改写旧版本，而是复制目标版本内容生成新的当前版本。
例如从 v1 恢复时：

```text
v1 -> v2 -> v3(基于 v1 恢复)
```

这保证任何历史问卷和版本记录仍然可追溯。

## 11. 跨问卷统计

跨问卷统计按题目根查找所有题目快照，再查找当前用户拥有且使用过这些快照的问卷。
系统按 `question_id` 过滤答卷中的答案，因此只统计真正回答过这道题的答卷。

- 单选和多选按选项文本合并不同版本的统计。
- 数字题计算回答人数、平均值、最小值和最大值。
- 文本题返回答案、所属问卷和提交时间。
- 共享题目的统计只显示当前用户自己创建的问卷，避免泄露其他用户答卷。
